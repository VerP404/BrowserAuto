# Ввод талонов ДВ4 / ОПВ (Web.ОМС medicalExamination)

Робот на базе логики `талоны2_1.ipynb`, но для форм:

| Тип | URL |
|-----|-----|
| ДВ4 | `http://10.36.0.142:9000/claim/medicalExamination/dv4` |
| ОПВ | `http://10.36.0.142:9000/claim/medicalExamination/opv` |

---

## Что заполняется

### Страница 1 (карта)
1. `#begin-date`, `#end-date`
2. `#enp` + поиск
3. `#doctor` — код врача (**можно пусто** — тогда поле пропускается, дописываете вручную)
4. `#request-result` — результат (из Excel)
5. `#service-place` / `#medicalExaminationPlace` — место обращения **= 1**
6. `#nextMonth` — период, по умолчанию **январь**
7. `#diagnosis-0` + `#is-dispensary-observation-0` — основной диагноз и ДН
8. `#diagnosis-1…` + `#is-dispensary-observation-1…` — сопутствующие (колонки `диагноз2`/`ДН2`…)

### Вкладка `#services-tab`
Список услуг **уже на странице**. Для каждой строки `i`:

| Колонка | Элемент | Что ставим |
|---------|---------|------------|
| Врач | `combobox-doctor-{i}` (второй с этим id — в ОМС дубль) | из карты или справочника |
| Выполнено | `combobox-failure-services-{i}` | по умолчанию `1` |
| Дата | `date-picker-services-{i}` | дата окончания талона |

Коды услуг **не трогаем** — они уже в форме.

## Excel

Создать шаблон:

```powershell
.\.venv\Scripts\python run_medical_exam.py --make-template
```

Лист **«талоны»** (`data/talons_dv_opv.xlsx`):

| Колонка | Обязательно | Пример |
|---------|-------------|--------|
| ЕНП | да | 1234… |
| начало | да | 01-01-26 |
| окончание | да | 15-01-26 |
| тип | да | ДВ4 или ОПВ |
| врач | **нет** | код или пусто (дописать вручную) |
| результат | нет | ДВ4 → 1,2,12,31,32,33,34; ОПВ → 1,2,31,32 |
| период | нет | январь |
| диагноз | нет | Z00.0 |
| ДН | нет | код с листа «ДН» |
| диагноз2… / ДН2… | нет | сопутствующие — **свой ДН на каждый** |
| корпус | нет | 1 |
| место | нет | 1 |
| выполнено | нет | Да |

### Коды ДН (лист «ДН»)

| Код | Значение | Когда |
|-----|----------|--------|
| 1 | Состоит | ДВ4, диагноз есть в ИСЗЛ:ДН |
| 2 | Взят | постановка на ДН (вручную) |
| 3 | Не подлежит | диагноза нет в ИСЗЛ:ДН |
| 7 | Состоит, проведено | **ОПВ**, диагноз есть в ИСЗЛ:ДН |
| 8 | Взят, проведено | ОПВ, новая постановка (вручную) |

В MosaicPortal (вкладка «Файл для робота») ДН считается автоматически по загруженному `load_data_iszl_dn`: для каждого МКБ (основной + сопутствующие) → 1/3 (ДВ4) или 7/3 (ОПВ). На листе «талоны» слева контекст (ФИО, участок, ИСЗЛ ДН, явка), справа поля робота — лишние колонки робот игнорирует.

## Справочник врачей по корпусу (заготовка)

Файл: `robots/oms/dv_opv/data/doctors_by_building.xlsx` (создаётся `--make-template`).

Сейчас **все услуги** получают врача из колонки «врач» карты (если она заполнена).  
Когда подготовите справочник — робот начнёт подставлять:

- точный код услуги + корпус → конкретный врач  
- `A09.05.%` / `*` → группа  
- роль `therapist` + пустой врач → врач карты  

Логика: `doctors_catalog.py` → `resolve_service_doctor()`.

## Связь с MosaicPortal

В портале: **Диспансеризация → ДВ взрослых → Файл для робота**.  
Выгрузка уже в формате этого робота (листы «талоны», «результат», «ДН»). После ввода в Web.ОМС данные подтягиваются журналами / детальной диспансеризацией.

## Замечания по DOM

В форме услуг ОМС **два** `input#combobox-doctor-{i}`: первый — код услуги, второй — врач. Скрипт берёт **последний**.
